*Extracted from skills/code-theory-reconstruction.*

Ask: **"If 'this system is like ___' had to be filled in one sentence, what would you put?"**

Wait for the user's answer. Then run the check: does each major module or component have a role in that metaphor?

- A module that fits → the metaphor is doing real work.
- A module that has to be jammed in → the metaphor is incomplete or wrong.
- A module with **no role at all** → the most interesting finding. Either the metaphor is missing something, or that module is doing something orthogonal to the rest of the system. Worth keeping as its own claim.

**Failure to find a satisfying metaphor is itself a strong diagnostic.** Don't paper over it with a weak metaphor for the sake of an answer. "I cannot yet metaphorize this system" is a real finding — it means the theory hasn't closed. Mark it, and let it bother the user until it resolves.

**Scope**: only use parts of the system already discussed in this conversation. Don't open new files to hunt for confirming evidence — the metaphor's job is to check what's already been seen, not to license fresh exploration.

This lens is mid-weight: heavier than a single question, lighter than a full synthesis ritual. If the user answers "the system is like ___" without quite knowing why, that's the signal something bigger is due.
